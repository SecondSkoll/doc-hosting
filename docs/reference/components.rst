Components
==========

API application and charm
-------------------------

``app.py`` exposes the FastAPI application from ``doc_hosting/``. The
``doc-hosting-api`` charm packages it with the ``fastapi-framework`` extension
on Ubuntu 24.04. Its required, single ``s3`` integration provides storage
settings; ``publish-token`` becomes ``APP_PUBLISH_TOKEN``.

Rock
----

``rockcraft.yaml`` builds the application for amd64 using the
``fastapi-framework`` extension, a bare runtime base, and Ubuntu 24.04 build
base. The build requires a root ``requirements.txt`` generated by ``uv export``.

Its dependency part applies two build fixes. First, it removes the install
directory's ``lib`` and ``lib64`` usr-merge symlinks so pip can install data
scripts such as jmespath's ``jp.py``; it then relocates site packages under
``usr/lib/python3.12``. Second, it removes the disposable source copy of the
root ``pyproject.toml`` so the plugin does not attempt ``pip install .`` on a
project without a build system.

Deployment services
-------------------

``scripts/deploy.py`` deploys these applications in the ``doc-hosting`` model:

.. list-table::
   :header-rows: 1

   * - Application
     - Role
   * - ``doc-hosting-api``
     - Registers builds, lists versions, and serves stored files.
   * - ``minio`` (``latest/edge``)
     - S3-compatible storage for documentation and registry data.
   * - ``s3-integrator`` (``2/stable``)
     - Supplies the required bucket, endpoint, and credentials through the
       ``s3`` relation and creates the configured bucket.

Scripts and CI
--------------

``scripts/deploy.py`` provides ``setup``, ``build``, ``deploy``, ``all``, and
``teardown``. ``scripts/publish.py`` uploads a built tree and then registers
it. The publish workflow builds and publishes on ``main``, ``v*`` tags, or
manual dispatch. The test workflow runs unit tests. Automatic documentation
checks invoke the Canonical reusable documentation-checks workflow.

Data flow
---------

The documentation builder produces ``dirhtml`` files. The publish script puts
each file in MinIO under the URL-shaped prefix, then sends metadata to the
authenticated API. The API stores a registry JSON object in the same bucket.
Readers request a documentation URL from the API, which loads the corresponding
object from S3. The public versions endpoint derives its response from the
registry.

See :doc:`../how-to/build-the-rock-and-charm` to build artifacts,
:doc:`http-api` for the service interface, and :doc:`storage-layout` for keys.
